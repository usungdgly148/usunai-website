# 手动受控发布流程

当前阶段不启用 GitHub 自动生产部署。每次发布由人工确认后执行。

## 1. 发布前

1. 确认当前分支已经合并到 `main`。
2. 执行 `npm run verify` 和必要的业务回归测试。
3. 检查 `git status` 必须干净。
4. 创建发布版本号和变更说明。
5. 在服务器创建带时间戳的文件级备份。

## 2. 发布边界

- 后端目标：`/opt/usun/server`
- 前端目标：`/opt/usun/dist`
- Nginx 配置仅在明确需要时单独发布。
- `/opt/usun-data`、`/opt/usun/.env` 和备份目录不得被发布覆盖。

## 3. 安装与启动

1. 文件先上传到服务器临时目录，不直接覆盖生产目录。
2. 在临时目录检查文件清单、语法和权限。
3. 精确安装本次变更文件。
4. 后端依赖发生变化时，在服务器执行锁定版本安装。
5. 重启 `usun.service` 并确认处于 active 状态。

## 4. 发布后验证

- 首页和管理后台返回正常状态。
- 登录状态正常。
- 至少验证一个智能体和一个工作流的核心路径。
- 后端日志没有新增持续性错误。
- 数据库、上传文件和知识库目录未发生意外变化。

验证通过后创建带说明的 Git 标签；失败则按回退文档立即恢复。
