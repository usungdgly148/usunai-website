# 微信小程序阶段 7 发布与回滚手册

## 发布通道

| 通道 | 构建命令 | 默认 API | 用途 |
| --- | --- | --- | --- |
| 开发版 | `npm run build:miniapp:development` | `http://127.0.0.1:8787` | 微信开发者工具本地联调 |
| 体验版 | `npm run build:miniapp:experience` | `https://www.usunai.top` | 内部与小范围真实用户验收 |
| 正式版 | `npm run build:miniapp:production` | `https://www.usunai.top` | 微信审核通过后的正式发布 |

体验版和正式版目前共用生产业务数据，但请求携带不同的环境与版本标识，监控可以区分来源。若以后需要隔离体验数据，可通过 `MINIAPP_API_BASE` 指向独立测试后端，无需修改业务代码。

每次构建会生成 `miniapp/dist/release-manifest.json`，记录环境、版本、Git 提交、API 地址和构建时间。该文件随构建产物交给微信开发者工具，但不提交 Git。

## 灰度顺序

1. 开发版：完成类型检查、阶段 1 至阶段 7 契约检查和本地构建。
2. 体验版：仅添加内部成员，验证登录、首页、分类、智能体、工作流、资产、订单和算力记录。
3. 小范围用户：使用微信小程序体验成员或审核前体验范围收集客户端错误与接口指标。
4. 正式版：确认关键指标无明显回退后提交微信审核并全量发布。

本阶段不包含微信支付，也不执行真实 Coze、DeepSeek、百炼、Qdrant 或 RAG 调用复测。

## 监控与隐私

管理员接口：`GET /api/admin/miniapp-metrics?windowMinutes=1440`。

指标包含登录失败率、API P50/P95、工作流成功率、对话首包 P50/P95、客户端渲染错误数量及最近安全事件。指标不保存用户输入、响应正文、账号、Cookie、Token、手机号、API Key 或 Authorization 请求头。

服务端最多保留最近 50,000 条小程序指标，并按最新记录优先查询，避免监控数据无限增长拖慢业务数据库。

## 回滚

1. 小程序代码回滚：在微信公众平台使用“版本回退”恢复上一正式版本；体验版则重新上传上一 Git 提交构建的 `miniapp/dist`。
2. 服务端回滚：部署前保留 `/opt/usun` 对应文件备份；异常时恢复上一版本的服务端文件并重启 `usun`。
3. 页面布局回滚：后台“小程序设计”使用已发布版本历史恢复上一布局，不需要重新发布小程序代码。
4. 回滚后验证：检查 `/api/health`、`/api/miniapp/v1/content` 和小程序登录状态；不以真实 AI 调用作为回滚验证条件。

## 发布门槛

- `npm run verify` 全部通过；
- 正式版清单中的 API 必须为 HTTPS 且不能是 localhost；
- 生产健康检查通过；
- 能在上一个 Git 提交和微信上一版本之间完成回退；
- AppSecret、用户 Token 和任何第三方密钥均未进入源码、清单或日志。
