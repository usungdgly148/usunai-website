# 微信小程序开源方案比较与 MVP 建议

> 调研快照日期：2026-08-30。Star、Fork、Issue 和提交数据会变化；GitHub 仓库的 `open_issues` 字段可能同时包含开放 Issue 与 PR。

## 一、最终建议

以 **Taro 4 + React + TypeScript** 作为小程序客户端工程底座，**TDesign MiniProgram 按需接入**通用 UI；登录、上传、分块流式、媒体预览和支付等关键能力直接调用 Taro/微信原生 API。

不套用完整商城或 AI 聊天模板，不引入 CloudBase，不复制现有后端与数据库。小程序作为第二个用户前端，通过新增的 `/api/miniapp/*` 适配层复用现有 Node、SQLite/KV、Qdrant、Coze、DeepSeek、RAG、算力、资产和订单逻辑。

后台“小程序设计”模块在现有 React 管理后台内开发受控的白名单 Schema 编辑器；不引入通用低代码运行时。

## 三、环境、依赖与第三方服务

### 本地开发环境

- Node.js 20 LTS。
- npm 或 pnpm，锁定 lockfile。
- Taro 4 CLI、React、TypeScript。
- 微信开发者工具和已认证的小程序 AppID。
- TDesign MiniProgram 仅安装实际使用的组件。

### 继续复用的服务

- 现有腾讯云服务器、HTTPS 域名和 Node 后端。
- 现有 SQLite/KV、Qdrant、百炼 embedding、Coze、DeepSeek 和 RAG。
- 现有图片 WebP/缩略图、资产、算力、套餐和订单数据。

### MVP 不新增

- 不新增 CloudBase、第二套数据库、第二个 AI 网关或微服务集群。
- 不新增通用低代码 SaaS、远程插件市场或外部页面运行时。
- 微信支付延期到资质和商品合规确认后再做。

## 四、可以直接复用的功能

### 来自 Taro/TDesign

- 小程序工程、React/TS 组件组织、路由和构建。
- 按钮、表单、上传、弹窗、图片预览、骨架屏、空状态、分页/加载状态。
- 对话输入、消息列表等 UI 思路；真实流式协议仍接现有服务器。

### 来自现有网站

- 用户、智能体、工作流、分类、推荐、历史、资产、算力、订单和后台数据。
- Coze 新旧版、DeepSeek 原生模型、RAG 与第三方密钥管理。
- 扣费、有效期、任务、资产入库和权限校验规则。
- 现有管理后台的内容配置和素材上传能力。

## 五、必须重新开发的部分

- 微信 `wx.login` code2Session、OpenID/UnionID 与现有 userId 的安全绑定。
- `/api/miniapp/*` 接口适配、统一错误码、分页、幂等和版本兼容。
- 小程序分块流式解析；长工作流任务 ID、轮询、恢复和后台切换处理。
- 小程序文件上传、视频/图片预览、合法域名和弱网重试。
- 小程序页面 UI，不机械复用网页 DOM/CSS。
- 管理后台“小程序设计”白名单 Schema、草稿/预览/发布/回滚。
- 真机错误采集、版本提示和灰度发布流程。

## 六、最小 MVP

### 先做技术风险闸门

1. Taro React/TS 空壳小程序能在真机打开。
2. 微信登录能映射到一个现有测试用户，并读取一条受保护数据。
3. 一个 DeepSeek/Coze 测试智能体能分块显示首字。
4. 一张图片能上传到现有服务器并正常预览。
5. 一个长工作流能返回任务 ID，切后台再回来后恢复状态。

这五项通过后再批量做页面，避免 UI 做完才发现核心链路不兼容。

### 第一版页面与能力

1. 微信登录与已有账号绑定。
2. 可配置首页：品牌、轮播/公告、分类、推荐智能体、推荐工作流、快捷入口。
3. 分类、搜索、列表和详情。
4. 智能体文字/图片对话、真实分块流式和历史。
5. 工作流参数、上传、任务提交/恢复、历史和媒体预览。
6. 用户中心：算力、有效期、算力记录、资产；订单记录只读。
7. 后台“小程序设计”V1：只设计首页，支持排序、显隐、有限属性、草稿、预览、发布和回滚。

### 明确延期

- 微信支付与充值。
- 任意自由画布、任意代码组件和完整多页面设计器。
- 知识库管理、管理后台全量小程序化。
- 营销裂变、优惠券、分销、订阅消息和客服系统。
- 支付宝/抖音等多端发布。

## 七、难度判断

Taro 工程和普通 UI 对熟悉 React 的开发者属于中等难度，但对不懂代码的普通用户仍不是“下载模板、改几张图就能上线”。难点集中在微信账号绑定、流式传输、长任务恢复、统一扣费与资产数据、合法域名以及真机兼容。采用上述组合可以减少 UI 重复开发，但业务适配仍必须按现有网站定制。
