## 二、MVP 页面与功能边界

### 第一版必须有

1. **微信登录与账号绑定**：新用户登录；已有手机号/邮箱用户经验证码绑定。
2. **可配置首页**：品牌区、轮播/公告、分类、推荐智能体、推荐工作流、快捷入口。
3. **发现工具**：分类、搜索、智能体与工作流列表、详情。
4. **智能体**：文字对话、能力允许时上传图片、分块流式回复、历史会话。
5. **工作流**：参数表单、文件上传、提交、状态恢复、历史记录、图片/视频预览。
6. **用户中心**：剩余算力、有效期、算力记录、资产、只读订单记录。
7. **账户与合规**：隐私政策、服务条款、账号绑定和账号注销。
8. **后台小程序设计 V1**：只编排首页，支持草稿、预览、发布、排序、显示/隐藏和单版本回滚。

### 第一版明确不做

- 微信支付和小程序内在线充值。
- 知识库管理后台小程序化。
- 管理后台完整小程序化。
- 任意 HTML、JS、CSS、远程插件或自由画布。
- 营销裂变、订阅消息、多端发布和复杂商城能力。

## 三、账号绑定与合并规则

1. 微信身份唯一键使用 `(appId, openId)`；`unionId` 仅在微信实际返回时作为辅助跨应用标识，不能假设一定存在。
2. 一个微信身份只能绑定一个网站用户；一个网站用户可以绑定多个经过验证的登录身份。
3. 微信新用户首次登录时创建或绑定普通用户，不创建管理员身份。
4. 已有手机号/邮箱用户必须通过短信或邮箱验证码验证后才能合并。
5. 禁止按昵称、头像、客户端提交的 OpenID、未验证手机号或相似姓名自动合并。
6. 出现“微信身份已绑定其他账号”等冲突时停止自动合并，提示用户处理或进入后台人工核查。
7. 解绑或换绑必须再次验证当前账号；后台操作需要审计记录。
8. 合并后继续使用原 `userId`，原余额、有效期、资产、订单和历史不得复制或重算。

## 四、隐私数据最小清单

### 登录和安全必需

- OpenID；微信实际返回时的 UnionID。
- 网站 `userId`、登录时间、必要的设备与网络安全日志。
- 手机号或邮箱仅在用户主动绑定已有账号时收集并验证。

### 使用功能时产生

- 用户主动提交的文字、图片和文件。
- 对话、工作流任务及历史记录。
- 用户资产、算力余额/流水、订单记录。

### 可选且应延后请求

- 微信昵称、头像等展示信息，仅在用户主动操作且功能确有需要时获取。

原则：不为“以后可能用到”提前收集，不把第三方 API Key、AppSecret、管理员 token、System Prompt 或支付私钥放入小程序包。

## 五、第一版充值与支付决策

阶段 0 默认结论：**MVP 不接微信支付**。

- 小程序显示算力余额、有效期、流水和套餐说明。
- 充值继续通过现有客服方式办理，订单记录只读。
- 微信支付放在阶段 6，待商户资质、类目、支付场景和回调域名全部核验后实施。
- 客户端任何“支付成功”状态都不能直接加算力；以后接支付也只能由服务端回调或主动查单入账。
